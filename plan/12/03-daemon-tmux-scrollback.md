# 03 — Daemon：tmux 環境自有化與可滾動的 scrollback（PV-04）

適用 skill：`go-daemon-development`（tmux 生命週期與所有權）＋ `terminal-websocket-protocol`
（「bounded scrollback」的那一條；本檔不改協定，但改了「scrollback 是什麼」的實質內容）。

## 1. 根因（已實測，2026-08-01，tmux 3.2a ＋ `@xterm/xterm` 5.5.0）

```text
tmux attach-session 的第一批位元組：
  1b 5b 3f 31 30 34 39 68   →  ESC[?1049h     進入 alternate screen
  1b 5b 3f 31 30 30 30 6c   →  ESC[?1000l     關閉滑鼠回報
  1b 5b 3f 31 30 30 32 6c   →  ESC[?1002l     關閉按鍵事件追蹤
  1b 5b 3f 31 30 30 36 6c   →  ESC[?1006l     關閉 SGR 擴充
```

兩件事合起來造成「滾不動」：

1. **xterm.js 的 alt buffer 沒有 scrollback。** tmux 一 attach 就切進去，所以 xterm.js 這一側
   永遠沒有可捲的內容 —— 使用者滾的是一個空的歷史。
2. **tmux 明確關閉滑鼠回報**，於是 xterm.js 的滾輪處理落到
   `if (!this.buffer.hasScrollback)` 這條分支，**把滾輪轉成方向鍵送給應用程式**
   （已於 5.5.0 bundle 核對）。這解釋了使用者感受到的兩種症狀：在 bash 裡往上滾會翻出歷史命令，
   在 TUI 裡會移動選擇項 —— 「不能捲動」其實是「捲動被翻譯成別的東西」。

修法後（`set -g mouse on`）：tmux 改送 `ESC[?1002h ESC[?1006h`，xterm.js 註冊自己的 wheel handler
並轉送 SGR 滑鼠事件，tmux 收到滾輪後進 copy-mode 捲自己的 history。**xterm.js 一行程式都不用改。**

另外兩項實測結論直接決定了 §2 的形狀：

| 實測 | 結果 | 後果 |
|---|---|---|
| 預設 socket 的 `history-limit` | **2000** | `FR-TERM-004.AC-04`（至少 5000 行）目前不成立；`session.scrollback_limit: 5000` 被寫進 config 卻從未被讀 |
| `new-session` 之後才 `set-option -t <s> history-limit 50000` | pane 仍回報 **2000** | history 必須在 pane 建立**之前**就位 → 只能靠 server 啟動時的 `-f <conf>`（或 `set -g` 後才建 session） |
| `new-session` 之後才 `set-option -t <s> mouse on` | attach 時**確實**送出 `1002h/1006h` | mouse 可以事後補 → 這是「server 早於新 conf 就已存在」時的救援路徑（§2.4） |

## 2. 設計

### 2.1 專用 socket

`session.New(ctmux.Client{}, …)`（`daemon/internal/connection/connection.go:101`）目前 `Socket` 為空字串，
也就是 cliora 的 session 全部落在**node 擁有者自己的預設 tmux server** 上。改為固定
`ctmux.Client{Socket: "cliora", ConfigPath: <resolved>}`。

| 決定 | 選擇 | 理由 |
|---|---|---|
| socket 名稱 | 常數 `tmux.DefaultSocket = "cliora"` | 與 session 名稱前綴（`Prefix = "cliora-"`）同一個命名邏輯；不可設定（多一個設定項只會多一個支援問題） |
| 為什麼要分開 | node 擁有者的 `tmux ls` 不再看到 `cliora-*`；我們的 `mouse on`／`status off`／`history-limit` 不會改到他的環境 | 這是本期唯一一個**必須**先做才能安全設定選項的前置動作。在共用 server 上 `set -g` 是在改別人的東西 |
| 既有 session 的處置 | 見 §2.4 | tmux 無法跨 server 搬 session，這個代價無法規避 |

`session/manager.go:116-119` 手工組 `attach-session` 參數的那段也要跟著走同一個 `Client.args()`，
否則 attach 會連到**另一個** server（症狀：`Exists` 為 true 但 attach 立刻退出）。
最小修法是把該段改成呼叫 `m.tmux.AttachArgs(name)`，讓 socket 與 `-f` 只有一個組裝來源。

### 2.2 daemon 自有的 tmux 設定檔

由 daemon 在啟動時**產生**（不是由 installer 靜態安裝），因為 `history-limit` 要跟著
`session.scrollback_limit` 走：

```text
# /run/agentd/tmux.conf — generated by agentd; edits are overwritten on restart.
set -g mouse on            # PV-04：滾輪進 copy-mode，見 plan/12/03 §1
set -g history-limit 5000  # ← session.scrollback_limit（FR-TERM-004.AC-04）
set -sg escape-time 10     # 預設 500ms 會讓 TUI 的 Esc 明顯延遲
set -g status off          # 產品自己提供框架；status line 會吃掉一列並顯示與產品無關的資訊
set -g default-terminal "xterm-256color"
set -ga terminal-features ",xterm-256color:RGB"
```

| 選項 | 為什麼在這裡 | 代價 |
|---|---|---|
| `mouse on` | ② 的修法本體 | 拖曳選取被 tmux 接手 → 需 Shift＋拖曳（`00-…md` D7，UI 要寫） |
| `history-limit` | `FR-TERM-004.AC-04` 從「寫了沒接線」變成成立 | 記憶體：每個 pane 的上限；5000 行 × 每行約數百 bytes，數量級是每 session 數 MB |
| `escape-time 10` | tmux 預設 500ms，claude／codex 都重度使用 Esc | 極低；這是 tmux 社群的標準建議值 |
| `status off` | 省一列、去掉與產品無關的資訊 | **copy-mode 少了視覺指示**（`[0/5000]` 原本顯示在 status-right）→ §2.3 的補償 |
| `default-terminal` ＋ `RGB` | xterm.js 支援 24-bit 色；不宣告會退成 256 色 | 無 |

檔案位置的解析順序（`tmux.ResolveConfigPath()`）：

1. `$RUNTIME_DIRECTORY`（systemd 在 unit 加上 `RuntimeDirectory=agentd` 後會設定它，
   並建立 `/run/agentd` 且屬於服務使用者 —— 這是 daemon 非 root 卻能寫的正解）；
2. `$XDG_RUNTIME_DIR/agentd`；
3. `filepath.Join(os.TempDir(), fmt.Sprintf("agentd-%d", os.Getuid()))`（rootless 開發與
   `scripts/e2e/run-stack.sh`）。

寫入用 `0600` ＋ 暫存檔 rename（原子）。路徑必須**穩定**：tmux server 的生命期長於 daemon，
路徑換了會讓下一次 `-f` 指到不存在的檔案（tmux 對此的行為是啟動失敗，症狀是所有 session 都開不起來）。

`unit` 的對應修改（`daemon/internal/install/systemd.go`）：加 `RuntimeDirectory=agentd`。
註解要寫清楚它是為了什麼 —— 這一行看起來像可有可無的整理，實際上是 §2.2 的前提。

### 2.3 copy-mode 的可用性

`status off` 之後，使用者在 copy-mode 裡沒有任何 tmux 提供的視覺回饋，而 copy-mode 會吃掉按鍵。
三層處理：

1. **tmux 預設的 wheel 綁定帶 `-e`**（`copy-mode -e`）：滾回底部時**自動離開** copy-mode。
   本期不覆寫任何 wheel 綁定，就是為了留住這個行為 —— 要在 `07-…md` 記下「不要為了微調而改綁定」。
2. **UI 提示**（`PV-08`）：終端機下方一行灰字
   「滾輪可檢視先前輸出（按 `q` 回到即時輸出）· 選取文字請按 Shift 拖曳」。
   兩句話都是本期新產生的操作知識，不寫出來使用者無從得知。
3. `set -g mode-keys` **不設定**（保持 tmux 預設 emacs 風格）：`q` 在兩種模式下都能離開 copy-mode，
   而選一種風格會讓另一群使用者的肌肉記憶失效。

### 2.4 既有 session 與既有 server 的處理

三種情況，都要有明確行為：

| 情況 | 行為 |
|---|---|
| 舊 socket（預設 socket）上有 `cliora-*` session | daemon 啟動時掃一次（`tmux list-sessions -F '#{session_name}'`，失敗即忽略），發現則 `slog.Warn("legacy tmux sessions found on default socket", "count", n)`；`doctor` 顯示 `[warn]` 與收拾方式。**不自動搬移、不自動 kill**（D5b） |
| 專用 socket 上的 server 早於現在的 conf（例如改了 `scrollback_limit` 後重啟 daemon） | `doctor` 比對 live server 的 `mouse`／`history-limit` 與期望值，不符則 `[warn]`：「需結束所有 session 後才會套用新設定」 |
| 新 session 建立時 server 已存在且 `mouse` 為 off | `Start` 在 `new-session` 之後補一次 `set-option -t <name> mouse on`（實測有效，§1 表格第三列）。**history-limit 補不了**，這是誠實的殘留限制，寫進 runbook |

`Start` 的補救 `set-option` 失敗不視為啟動失敗（session 已經在跑；滾不動比開不起來好），
但要 log 一行。

### 2.5 `scrollback_limit` 接線與下限

- `SessionConfig.ScrollbackLimit` 首次被讀取（今天只被寫入，`install/plan.go:117`）。
- `Validate`：缺項或 < 5000 → 提升到 5000 並記 `slog.Warn`。理由：`FR-TERM-004.AC-04`
  是需求下限，設定檔不該能違反它；但直接報錯會讓既有 node（寫了較小值的手改設定）起不來。
- 上限：> 200000 → 夾到 200000 並警告（記憶體保護；一個手滑多打三個零的值會讓 pane 吃掉 GB 級記憶體）。
- `doctor` 印出實際生效值（來自 live server 的 `#{history_limit}`，不是來自設定檔 —— 兩者可能不同，
  而使用者要知道的是前者）。
