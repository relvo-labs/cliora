### 1.2 M-SC-1 — 機密的實際大小與典型數量

**擋 `SC-06`**（contract 的三個上限）。

**✅ 已量（2026-08-13）**，實測而不是估計：

| 輸入 | 實測 | 怎麼量的 |
|---|---|---|
| GitHub fine-grained PAT | **93 字元** | `github_pat_` ＋ 22 ＋ `_` ＋ 59 的固定格式 |
| GitHub classic PAT | 40 字元 | `ghp_` ＋ 36 |
| GitLab PAT | 26 字元 | `glpat-` ＋ 20 |
| ed25519 私鑰（OpenSSH 格式） | **399 bytes**（7 行） | `ssh-keygen -t ed25519` |
| **RSA-4096 私鑰** | **3 369 bytes** | `ssh-keygen -t rsa -b 4096` |
| 一般 env 機密 | < 200 bytes（判斷，無母體） | |
| 一張卡典型宣告幾個 | 無母體 → 判斷：**8 是寬到不會擋人、窄到裝得下的數字** | |

**定案**：單值上限 **8 KiB**（RSA-4096 的 3 369 bytes 有 2.4 倍餘裕，
而它是最大的合法輸入）、`maxItems` **8**、`context` 上限 **32768**。

⚠️ **8 × 8 KiB = 64 KiB，單這一格就吃光訊框。** 所以 schema 的上限
**不能是唯一的保護**——D2 的 Central 端檢查是必要的，而不是保險。

⚠️ **UI 要勸退 RSA-4096 而不是擋它**（`06-…md` §1.3）：它合法，但一枚就吃掉
8 KiB 預算的 41%，而 ed25519 只要 399 bytes ——**8.4 倍的差距**，
而這句話用實測數字寫比用「建議用 ed25519」有效得多。

### 1.3 M-SC-2 — 去識別的成本

**擋 `SC-07`**（D6 的實作層級）。

| | |
|---|---|
| 問題 | 對每一個外送訊框的每一個字串值做 5 次 `strings.ReplaceAll`，成本多少？ |
| 怎麼量 | Go benchmark：32 KiB 的 chunk × 5 個機密值 × 遞迴 payload。再跑一次終端延遲量測（`scripts/ar/measure_terminal_latency.py`），在有 run 全速輸出時比對 |
| 判準 | ⚠️ **原本寫「p95 不比基線高 20% 以上」，而 `SC-00` 證明那個判準落在雜訊底下**：同一台機器兩次 idle 量測的 p95 差了 **27%**（0.980 → 1.242 ms），`max` 從 1.489 跳到 5.411。**改成**：連續量三次取 **p50 的中位數**，在「有 run 全速輸出」與「沒有 run」兩種情況下各量三組，比較那兩組的中位數；p95 只作參考不作判準（`08-…md` §3 第 3 條） |

## 2. `SC-07b` 開工的第一件事（不是量測，是實測）

### 2.1 淺 clone 之後能不能 push 一條新分支？

`04b-…md` §4.2。V2.2 用 `--depth 1 --single-branch`，而
**某些 host 對 shallow push 有限制**。

- 對本地 bare 遠端與 Traqora 各推一次。
- 不成立時的退路是 push 之前 `git fetch --unshallow`，
  而**那會讓大 repo 的 run 多等一次完整 fetch**——那個秒數要量並記在這裡。

**這件事不能從文件讀出來，要跑一次。**

## 5. 三個不會被量測回答的問題

寫在這裡，因為它們看起來像量測問題而其實不是——
把它們留在這一份文件裡，是為了讓下一個人不要花時間去量。

1. **「授權邊界只有 enrollment 夠不夠安全？」**
   這是一個姿態選擇（2026-08-12 裁決），不是一個可以量的東西。
   能量的是它的**代價**：`M-SC-5` 之類的東西告訴我們 tag 被誤用了多少次，
   但「夠不夠」永遠是人的判斷。

2. **「去識別漏掉了多少？」**
   無法量——漏掉的定義是「我們沒認出來的編碼形式」。
   ADR 0032 明寫它是盡力而為，而第二道保證是可撤銷 ＋ 保留期。
   **要量的話只能量第二道**：從「發現外洩」到「機密被撤銷」花多久。

3. **「主金鑰放環境變數風險多大？」**
   同上，是一個信任邊界的選擇。能做的是把 KMS 升級路徑保持暢通
   （信封加密 ＋ `key_version`），而那已經做了。
