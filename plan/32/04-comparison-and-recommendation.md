## 3. 建議方向與信心

**建議：以 A（克制編輯式）為基底，帶進 C 的一條規則——「需要使用者做事時，那個動作是整寬按鈕」**；
B 的「有標籤的狀態格」不採用為預設，但保留為 200% zoom／大字級下的替代排版候選。

理由（依重要性）：

1. 痛點地圖裡最大的問題是結構（P1、P2、P5、P6），三個變體都已解決；在結構相同時，A 的外框最少、終端最多、離 VDS 最近、實作成本最低。
2. A 的弱點是「無標籤的控制權」與「尾端小按鈕容易漏看」；C 的整寬動作按鈕正好補這一點，而且只在 Viewer／斷線時出現，平常不佔高度。
3. B 的標籤最清楚，但每個狀態都多付 30–60px，而且把中文擠進等寬 meta，閱讀最差；它回答的是「資訊密度」，而使用者的回饋是「太制式」，不是「資訊不夠」。

**信心：中低（約 55%）。** 原因寫清楚：

- 沒有任何真機、真人觀察；評等全是研究者判斷。
- A 與 C 在終端畫面幾乎一樣，這個建議其實主要建立在清單與狀態列上。
- 「AI 制式化」是使用者的一句話；我們把它解讀為「外框堆疊＋膠囊＋桌面式提示」，這個解讀本身需要驗證。
- D1／D2（深色終端）可能就是使用者最強烈的感受；它修好之後，對三個變體的偏好可能會變。

## 4. UAT 必須確認的事

建議在 D1／D2 修正**之後**做（否則比較的是「深色終端 vs 明亮終端」而不是變體），iPhone Safari 與 Android Chrome 各至少一台，
每位觀察者看 A 與 C（B 作為對照可選），使用合成資料。

| # | 任務／問題 | 通過條件 |
|---|---|---|
| U1 | 打開清單，指出哪個 Session 失敗、哪個在另一台 Node | 不需要點開 |
| U2 | 在 Viewer 狀態下，回答「你現在能打字嗎？為什麼？怎麼做？」 | 不解讀終端內容即可回答（#75 驗收第 2 項） |
| U3 | 斷線狀態：「畫面上的輸出是最新的嗎？」 | 能說出「不是／已停止更新」 |
| U4 | 可提權 Node：「這台機器有什麼要注意的？」 | 能說出 sudo／root 或沙箱停用 |
| U5 | 從活動（假說）或預覽拒絕回到原生終端 | 一次點擊內完成 |
| U6 | 開啟系統 shell，再說出它與「終端機」分頁的差別 | 能說出「關掉會終止」或「不受工作目錄限制」 |
| U7 | 轉成橫向繼續看輸出 | 不迷路、終端仍可讀 |
| U8 | 開放問題：「哪一版比較不像『AI 樣板』？為什麼？」 | 記錄原話，不引導 |
| U9 | VoiceOver／TalkBack：朗讀狀態列與分頁 | 三格狀態被分開、帶標籤讀出 |

UAT 結果與選定方向記錄在本目錄的後續版本（v0.2）；在那之前，任何一個變體都不得被描述為「已選」。
