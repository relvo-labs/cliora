# 02 — 資訊層級重整（一套 IA，三個變體共用）

三個視覺變體（`03-…md`）的 DOM 結構與行為完全相同，差別只在 CSS。這一份定義那套共同結構。

## 1. 小螢幕一次要回答的四個問題

打開 Session 詳情的第一眼，不捲動、不展開，就要能回答：

| 問題 | 回答它的元素 | 位置 |
|---|---|---|
| **是哪個 Session？** | Session 名稱（標題）＋「Runtime · Node 名稱 · 工作目錄最後一段」 | Session 列（第一列）；完整 id 與完整路徑在 `⋯` |
| **我現在能不能接手？** | 控制權：「你有控制權」／「唯讀 · 他人持有」／「輸入已停用」／「唯讀（已結束）」 | 狀態列（第二列）第三格 |
| **正在發生什麼？** | Session 狀態與連線狀態，**分開兩格**；posture 另一條警示帶 | 狀態列第一、二格；posture 帶緊接其下 |
| **下一步是什麼？** | 只有需要時才出現的一個動作：「取得控制權」或「重新連線」 | A/B：狀態列尾端。C（v0.2）：「重新連線」為狀態列整寬按鈕；「取得控制權」為終端底部整寬列，**佔據輸入的位置**——Viewer 看不到任何像是可以打字的地方 |

三格狀態**永不合成一個綠燈**（`StatusBar.vue` 檔頭、`FR-TERM-005.AC-06`）：
「執行中＋已斷線」要按重新連線，「已結束」按了沒用——合在一起就分不出來。

```
│ ● 執行中  ● 已連線  你有控制權   [動作] │  狀態列 ≥44px（role=status）
├──────────────────────────────────────┤
│ ⚠ 可提權：此 Node 可經 sudo 取得 root │  posture 帶：僅在有 posture 時出現，永不收進選單
├──────────────────────────────────────┤
│ 終端機   檔案                     [🖼] │  單排分頁 44px（＋受管 Session 的「活動」、開啟中的「系統 shell」）
├──────────────────────────────────────┤
│                                      │
│  終端機（貼邊、明亮 pocket 調色盤）     │  唯一的主要內容；不包卡片（style.md §18）

└──────────────────────────────────────┘
```

390×844 的量測（原型，扣除原型控制列）：終端從 **y=145**（B：154）開始，**38–39 列**；
現況 y=267、28 列。有 posture 時 35 列；已斷線時 32–35 列（視變體）。

## 3. 合併、移除與移位

| 現況元素 | 處置 | 理由 |
|---|---|---|
| App header（漢堡、Cliora、頭像＋姓名＋角色） | **Session 詳情不顯示**；改為 Session 列的「‹ 返回 Sessions」 | 詳情頁的全域導覽只有一個用途：回到清單。帳號與其他頁面從清單頁進入 |
| Session header ＋「顯示 Session 資訊」揭露鈕 | 合入 Session 列；完整 id、Node、Runtime、完整路徑、字級、系統 shell、終止 → `⋯` 底部 sheet | 揭露鈕 11px、無命中區墊高；資訊在 sheet 裡有完整寬度 |
| posture 膠囊（在名稱旁） | 移到**獨立警示帶**，帶圖示與完整句子；橫向時縮成短字樣但仍在第一列 | ADR 0023 D10：打字前可見。膠囊與名稱搶寬度是 D3 的原因之一 |
| 「終端機／檔案」大切換 ＋「CLI／TERMINAL」分頁 | **合成一排**底線分頁：「終端機」「檔案」 | 兩套詞彙描述重疊的東西；「CLI」與「TERMINAL」對手機使用者沒有意義 |
| system shell 分頁（常駐） | 從 `⋯`「開啟系統終端機（此 Node 的 shell）」開啟；開啟後才出現「⚠ 系統 shell」分頁，帶 × 關閉 | 見 §5；是否在手機暴露仍待決（Q2） |
| 圖片投放列 ＋ 桌面提示 | 分頁列右側一個「附加圖片到 CLI」圖示鈕；僅 writer ＋ `can_upload_files` ＋ `image_upload` ＋ Session 執行中 | 行為與授權條件不變（ADR 0024），只改呈現；Session 結束時不再出現（D9） |
| 底部狀態列 ＋ 字級控制 | 狀態移到頂部狀態列；字級移入 `⋯` | 答案要在問題旁邊 |
| gap／斷線／結束的通知 | 終端上方一條帶狀說明（中性或警示），**不改終端像素** | 禁止 CSS filter／invert／重新上色（`plan/29/07` MS-19） |

## 4. 原生終端一觸可達

- 既有 Session：打開就是終端機（預設分頁）。
- 受管 Session（假說）：預設「活動」，「終端機」分頁永遠在同一排；活動底部固定「回覆與確認在終端機進行 ［終端機］」；
  等待確認的事件本身帶「到終端機處理」。
- 預覽拒絕（例如檔案過大）：「下一步：在終端機用 `tail` 或 `less` 查看 ［到終端機］」。
- runtime 不支援結構化事件：活動分頁只剩「此 Session 只支援原生終端機 ［開啟終端機］」。

測試（`test_prototype.py` 的 IA invariants）斷言：16 種詳情情境 × 3 變體 × 直式與橫式，
「終端機」與「檔案」分頁都可見。

## 5. 主 CLI 與系統 shell 不可混淆

| | 主 CLI（`cli`） | 系統 shell（`terminal`） |
|---|---|---|
| 分頁名 | 終端機 | ⚠ 系統 shell（警示色、帶圖示） |
| 如何出現 | 永遠在 | 只能從 `⋯` 主動開啟 |
| 關閉語意 | 沒有關閉鈕；離開＝detach，Session 繼續 | × 關閉＝**終止這個 shell**（ADR 0021），朗讀「系統 shell 已關閉並終止；主 CLI 仍在執行」 |
| 內容區 | 一般 | 上方常駐警示帶：「直接操作此 Node 的 shell，不受 workspace 路徑限制；此 Node 可經 sudo 取得 root。關閉即終止這個 shell；主 CLI 不受影響。」；終端左緣 3px 警示色邊線 |

視覺簡化**不能**讓這兩者看起來一樣；三個變體共用這組區別。

## 6. 其他畫面

**清單**：一列 header（漢堡、字標、頭像）；標題列「Sessions 5 / 5 ［＋ 新建］」；搜尋＋ Runtime 篩選同一列；
每列：名稱＋狀態字樣（失敗帶圖示）、「Runtime · Node 名稱 · 相對時間」、完整路徑（起頭截斷、`<bdi>` 隔離，修掉 D4）。
順序沿用伺服器順序（`plan/29/01` §1 禁止自創活動度排名；是否按狀態分組是 Q5）。
空清單與「無符合結果」是兩種訊息、兩種下一步。

**建立**：全螢幕 sheet（非置中對話框）；Node（含線上／離線、可提權標記；離線不可選）→ 選到可提權 Node 時先出警示帶 →
Runtime 兩顆單選 → 工作目錄＋最近使用 → 名稱（選填）→ 取消／建立。繁中。

**檔案**：搜尋框＋範圍說明（沿用現有文案）→ 麵包屑（可橫向捲動）→ 列表（資料夾帶 ›，檔案帶大小與時間）。
**預覽**：全幅；檔案列「‹ 檔名 · 唯讀 · Session · 大小 · 編碼 ［換行］［⋯］」，檔名只出現一次；
連線異常時狀態列會回到預覽上方（不讓斷線躲在全幅預覽後面）；拒絕態不顯示工具鈕。
Escape 與返回鍵回到清單並把焦點還給開啟的那一列（沿用 `plan/31` BP-06）。

**錯誤／無權限**：保留 Session 列（返回＋id），卡片沿用 ErrorNotice 四段，加「回到 Sessions」。

**橫向（高度 ≤500）**：Session 列（縮短）＋狀態列＋posture 短字樣＋分頁合成**一列 44px**；終端 17–18 列（現況 8 列）。
這需要改變「手機」的判定（目前只看寬度，D8），是 Q4。

**鍵盤**：框架高度跟著 `visualViewport` 縮（原型以 `--kb` 模擬 320px）；狀態列與分頁不固定、不浮動，
被鍵盤推上去可以，被蓋住不行（`plan/29/04` MS-02）。直式 390×844 鍵盤開啟時仍有 19–20 列；
橫向鍵盤開啟時終端幾乎不剩——這是 `MS-OM-06` 的真機題目，原型不假裝解決。
