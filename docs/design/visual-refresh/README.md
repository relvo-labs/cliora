## 原型與文件的關係

色彩表的「原型值」忠實記錄目前CSS；文字對比修正與各風格布局是下一步規格。現有原型以同一個主要版面展示五種主題，並未完成五張概念圖的全部版型差異。
例如Industrial的水平導覽、Studio的側欄摘要、Midnight的精簡側欄與面板間距仍為提案。

Porcelain與Studio的次文字／主按鈕配對存在未達4.5:1目標的項目；各文件明列改善值。淺色外框下的深色活動分頁也須指定獨立文字色。

> **修訂（`plan/28`，2026-09-08）。** 上面那一段當時漏了兩件事，兩件都在各文件的對比表裡補上並修正：
>
> 1. **對比表只驗了三組配對**，而**導覽與分頁選中態**（`accent.primary` 文字疊在 `accent.subtle` 底上）
>    沒有被驗過——Porcelain 實測 **4.13:1**、Studio **3.37:1**，兩者都不通過。
>    處置是新增 `accent.strong`（Porcelain `#1B54C4` = 5.90:1、Studio `#984D2E` = 4.83:1）。
> 2. **第三列「原型主按鈕文字／accent.primary」是拿 `surface.canvas` 當按鈕文字算的**，
>    而同一頁下面就寫著「不得以 canvas 字色推導所有按鈕文字」。已改為明確的
>    `text.onAccent` ／ `accent.strong`。
>
> 另外，`border.control` 的驗收面從「`surface.default` 與 `surface.canvas` 兩者」
> 擴為**三者**（加上 `surface.raised`）：對話框與選單是 raised 而它們裡面有輸入框。
> 五款主題共 195 組配對的實測結果全部通過，清單由元件契約產生而不是由 token 表產生
> （從 token 表出發正是漏掉第 1 點的原因）。

## 如何選定

先比較主要操作頁，再看Sessions與Nodes延伸。選擇時記錄：

| 決策 | 選擇（2026-09-08 核准） |
|---|---|
| 主要風格 | **Graphite**（預設，深色） |
| 次要／淺色主題 | **Porcelain**。驗收矩陣因此是 2 主題 × 3 斷點 = 6 組 |
| 導覽形式 | **可收合側欄**（展開 208px ／ 收合 64px 圖示列，桌面可手動＋斷點自動） |
| 預設資訊密度 | **標準**（表格列 48px、控制項 36px、觸控目標 44×44px），單一組不可切換 |
| 是否混搭 | **只取 Graphite 的版型**。Midnight／Studio／Industrial 的色值進主題表，**版型差異不實作**、不進切換器、不列入驗收矩陣 |
| 核准與日期 | 使用者核准，2026-09-08。ADR 0027 accepted；執行規格見 [`plan/28/`](../../../plan/28/README.md) |

**縮減矩陣的記錄**（共用規範要求「正式選定僅支援部分主題時，縮減矩陣需明確記錄範圍」）：
沒有被驗的是 Midnight／Studio／Industrial 的**任何**畫面、這三款的版型差異
（Midnight 的精簡導覽、Studio 的側欄摘要、Industrial 的水平導覽）、
Studio 的 `accent.strong` `#984D2E`（算術通過 4.83:1，但沒有在瀏覽器裡看過）、
緊湊密度，以及 Command Palette。這張清單同時進 release note——
否則「支援五種主題」會被讀成「五種都驗過了」。

## 文件驗證

本次核對五份風格文件的token鍵、RGB色值、三組文字對比配對及相對連結。對比使用標準sRGB線性化後的相對亮度比值計算，不包含透明度、字型渲染或狀態疊加。
未執行瀏覽器視覺／互動驗收或完整產品測試；各驗收勾選框刻意保持未勾選。
