# Design System Starter

Use `cliora-project-context`; treat `research/style.md` as canonical. Inventory CSS variables, theme overrides, wrappers, and hard-coded values. Map primitives to semantic surface, text, border, focus, action, feedback, and status tokens. Keep `theme/tokens.css` and `theme/themes.ts` in lockstep through `theme.contract.test.ts` — two sources exist because CSS needs a custom property while xterm and Monaco need resolved strings, and that test is the fuse for the cost. **Tokens have a theme dimension, and every theme must define every token**: chained `var(--x, fallback)` is forbidden as a way to cover a gap, because a missing token inherits the previous theme's colour instead of failing, which reads as merely odd in a screenshot review and therefore ships. Define xterm and Monaco exceptions. Cover focus, keyboard, disabled, loading, error, contrast, reduced motion, and labels. Migrate incrementally. Do not introduce arbitrary palettes or unsupported themes, and do not ship a theme the acceptance matrix has not covered — values passing the contrast test is not the same as a theme having been looked at in a browser. Contrast is **measured and reported per pair with its two colours**, never declared from a single value; and the pair list comes from the component contracts, not from the token table — building it from the token table is exactly how five design documents all missed `accent.primary` on `accent.subtle`, the selected state of navigation and tabs.
